# CLAUDE.md

Agent guide for `capacitor-native-navigation-bar`. Read this before touching any
file in this repository.

---

## What this is

A **Capacitor 7** plugin (npm package, **ESM only**) that renders native
navigation chrome — a navbar and a tab bar — on top of a Capacitor WebView,
and plays native snapshot transitions while JavaScript swaps routes. The
plugin does not read or report device safe-area/inset information; hosting
apps handle their own safe-area layout (e.g. `env(safe-area-inset-*)` in CSS).

- Package name: `capacitor-native-navigation-bar`
- Bridge name (must never change): `NativeNavigation`
- iOS package/pod name (auto-derived by CLI): `CapacitorNativeNavigationBar`
- License: MPL-2.0 — every source file must keep its `/* This Source Code Form … */` header.
- Capacitor 8 support is **out of scope** for this release. Do not add
  Capacitor 8 aliases, ranges, or dual-typecheck configs — see
  [What NOT to do](#what-not-to-do).

## ESM-only packaging — do not add back a second format

`tsdown.config.mjs` emits exactly one artifact: `dist/index.js` (ESM) +
`dist/index.d.ts`. There is no CommonJS build, no `.d.cts`, and no IIFE/UMD
bundle. `package.json` has no `require` export condition and no `unpkg` field.

Do not:

- add a `"require"` condition back to `exports`
- add an IIFE/UMD format back to `tsdown.config.mjs`
- add an `"unpkg"` or `"browser"` field to `package.json`
- add `"type": "commonjs"` (this package is `"type": "module"`)

**`sideEffects` is intentionally absent** from `package.json`. `registerPlugin()`
in `registry.ts` runs at module scope; tree-shaking must not strip it. This is
a deliberate, documented tradeoff (see `publint`'s tree-shaking suggestion in
`pnpm run check:package` output) — do not "fix" it by adding `sideEffects: false`
unless the registration architecture itself changes.

## Naming constraints — run `pnpm run check:wiring` if you touch these

The plugin only loads in Capacitor if these four names agree exactly:

1. `registerPlugin("NativeNavigation")` in `src/registry.ts`
2. `public let jsName = "NativeNavigation"` in the Swift plugin class
3. `@CapacitorPlugin(name = "NativeNavigation")` in the Java plugin class
4. The iOS pod/SPM package/library name must equal `fixName("capacitor-native-navigation-bar")` = `CapacitorNativeNavigationBar`

`scripts/check-wiring.mjs` asserts all of the above plus platform floors and
build baselines (iOS 15.0, Android minSdk 30, SDK 36 fallbacks, Java 21, AGP
8.13.2, Gradle 8.14.3, stable AndroidX fallbacks, ES2020,
`capacitor-swift-pm` pinned `from: "7.0.0"`, and
`peerDependencies` pinned to `^7.0.0`). It runs as part of `pnpm run lint`. If
it fails, the plugin may silently fail to load or drift from the documented
release policy.

## Platform floors — this plugin's own policy, higher than Capacitor 7's

| Platform | This plugin's floor | Capacitor 7's own floor | Consequence                                                                                                                                        |
| -------- | ------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| iOS      | 15.0                | 14.0                    | apps on the Capacitor 7 template default (14.0) must raise their own Podfile/Xcode deployment target to 15.0                                       |
| Android  | 30 (Android 11)     | 23                      | apps must use `minSdkVersion` 30, `compileSdkVersion` 36, and AGP 8.9.1+; the standalone baseline is AGP 8.13.2 / Gradle 8.14.3                    |
| Node     | 22.13.0             | n/a (build-time only)   | only affects building this package from source; floor is pnpm 11.9.0's own minimum, not Node 22 LTS's launch version (22.11.0) — see `PLATFORM.md` |

All iOS APIs newer than 15 must be behind `if #available(iOS …)`. All Android
APIs newer than 30 must be behind `if (Build.VERSION.SDK_INT >= …)`. Do not
raise these floors further without updating `PLATFORM.md` and
`check-wiring.mjs` together.

**Enforcement differs by platform/toolchain — verified, not assumed:**

- **Android**: `android/build.gradle`'s `minSdkVersion 30` is a **hard-coded
  literal**, not the usual `project.hasProperty(...) ? rootProject.ext... :
fallback` pattern every other version in that file uses. That pattern was
  tried first and empirically found to let an embedding app's lower value
  silently win with **no build error**, defeating this plugin's Android 11
  support policy. Do not "simplify" this back to the conditional form.
- **iOS SPM**: hard-fails the build on a deployment-target mismatch (verified).
- **iOS CocoaPods**: does **not** fail the build on a mismatch (verified) —
  raising the app's Podfile target is a correctness recommendation, not a
  build requirement, for this dependency manager specifically.

`peerDependencies` is `@capacitor/core: ^7.0.0`. There is a single
`tsconfig.json` (no Capacitor-8 variant), a single `devDependencies` set of
`@capacitor/*` packages pinned to the 7.x line, and `Package.swift` pins

a separate release, not something this package spans today.

## No safe-area/inset reporting

The plugin does not compute or expose safe-area or content-inset information
in any form — no CSS variables, no `insets` return value, and no change
event. Native chrome (navbar/tabbar) is positioned at the raw view edges on
both platforms; hosting apps are responsible for their own safe-area layout
(e.g. `env(safe-area-inset-*)` in CSS) and for avoiding overlap with the
native bars. Do not reintroduce inset computation, CSS variable injection, or
a `configure({ contentInsetMode })`-style option — this was deliberately
removed; see git history around the "remove safe-area logic" change for
context.

## Custom elements (components.ts)

`defineNativeNavigationElements()` registers three custom elements:

| Element                            | Maps to                        |
| ---------------------------------- | ------------------------------ |
| `<cap-native-navigation-provider>` | `NativeNavigation.configure()` |
| `<cap-native-navbar>`              | `NativeNavigation.setNavbar()` |
| `<cap-native-tabbar>`              | `NativeNavigation.setTabbar()` |

**Coalescing:** attribute changes are batched per microtask and serialized via a
`syncTail` promise chain. A rejected native call is swallowed (not an unhandled
rejection) so the queue stays alive.

## Events

Each event is emitted via both `NativeNavigation.addListener(...)` and a
`CustomEvent` on `window` under the name `capNativeNavigation:<eventName>`.

| Event name        | Payload type                      |
| ----------------- | --------------------------------- |
| `navbarBack`      | `NativeNavigationBackEvent`       |
| `navbarItemTap`   | `NativeNavigationBarItemTapEvent` |
| `tabSelect`       | `NativeNavigationTabSelectEvent`  |
| `transitionStart` | `NativeNavigationTransitionEvent` |
| `transitionEnd`   | `NativeNavigationTransitionEvent` |

`transitionEnd` can also be emitted by the native transition **watchdog** (see
`PLATFORM.md § Transition lifecycle safety net`) if `finishTransition` is
never called or the app is backgrounded mid-transition — in that case
`duration` is `0`. This is a defensive recovery path, not a new event.

## What NOT to do

- Do not rename the bridge (`NativeNavigation`) without updating Swift, Java, and
  running `check-wiring`.
- Do not raise platform floors further without updating `PLATFORM.md` and
  `check-wiring.mjs`; do not lower them without checking `PLATFORM.md`'s
  known-limitations and confirmed-defects history first.
- Do not remove or alter `/* This Source Code Form … */` headers in any source file.
- Do not add `sideEffects: false` to `package.json` (see ESM-only section above).
- Do not merge `registry.ts` into `index.ts` or `components.ts` (creates a
  circular module graph).
- Do not declare `"type": "commonjs"` — the package is ESM only.
- Do not add a `"require"` export condition, a `.cjs`/`.d.cts` build, or an
  IIFE/UMD bundle back — this package is ESM only (see above).
- Do not add Capacitor 8 support (aliases, ranges, dual tsconfig, dual
  typecheck scripts) to this release — it is Capacitor 7 only.
- Do not add `CLAUDE.md` to the npm `files` array.
- Do not reintroduce safe-area or content-inset reporting (CSS variables, an
  `insets` return value, a `safeAreaChanged`-style event, or a
  `contentInsetMode` option) into the plugin, and do not reintroduce
  safe-area-aware positioning of the native navbar/tabbar — this was
  deliberately removed; native chrome is positioned at the raw view edges and
  hosting apps own their own safe-area layout.
