# CLAUDE.md

Agent guide for `capacitor-native-navigation-bar`. Read this before touching any
file in this repository.

---

## What this is

A **Capacitor plugin** (npm package) that renders native navigation chrome — a
navbar and a tab bar — on top of a Capacitor WebView, reports safe-area insets
as CSS variables, and plays native snapshot transitions while JavaScript swaps
routes. Supports **Capacitor 7 and Capacitor 8+** from a single package.

- Package name: `capacitor-native-navigation-bar`
- Bridge name (must never change): `NativeNavigation`
- iOS package/pod name (auto-derived by CLI): `CapacitorNativeNavigationBar`
- License: MPL-2.0 — every source file must keep its `/* This Source Code Form … */` header.

## Three build artifacts and why

`tsdown.config.ts` emits three separate artifacts. Do not collapse them.

| Artifact            | Format      | Condition   | Why it exists                                      |
| ------------------- | ----------- | ----------- | -------------------------------------------------- |
| `dist/esm/**`       | ESM         | `import`    | Bundler-friendly; keeps dynamic `import('./web')` so native apps never load the web fallback |
| `dist/plugin.cjs`   | CommonJS    | `require`   | `require()` consumers and older bundlers           |
| `dist/plugin.d.cts` | CJS types   | `require`   | `"type":"module"` makes `.d.ts` ESM; a CJS consumer needs `.d.cts` to avoid TS1479 |
| `dist/plugin.js`    | IIFE        | `unpkg`     | CDN / `<script>` usage; global name `capacitorNativeNavigationBar` |

Build target is **ES2017** — mandatory, not a mistake. Capacitor's minimum
Android System WebView (v55) predates optional chaining and nullish coalescing.

**`sideEffects` is intentionally absent** from `package.json`. `registerPlugin()`
in `registry.ts` runs at module scope; tree-shaking must not strip it.

## Naming constraints — run `pnpm run check:wiring` if you touch these

The plugin only loads in Capacitor if these four names agree exactly:

1. `registerPlugin("NativeNavigation")` in `src/registry.ts`
2. `public let jsName = "NativeNavigation"` in the Swift plugin class
3. `@CapacitorPlugin(name = "NativeNavigation")` in the Java plugin class
4. The iOS pod/SPM package/library name must equal `fixName("capacitor-native-navigation-bar")` = `CapacitorNativeNavigationBar`

`scripts/check-wiring.mjs` asserts all of the above plus platform floors
(iOS 14.0, Android minSdk 23, SPM range `"7.0.0"..<"10.0.0"`). It runs as part
of `pnpm run lint`. If it fails, the plugin will silently not load in apps.

## Platform floors — do not raise them

| Platform | Floor  | Why                                               |
| -------- | ------ | ------------------------------------------------- |
| iOS      | 14.0   | Capacitor 7 minimum; Pod and SPM must match       |
| Android  | 23     | Capacitor 7 minimum; no `Collection.stream()` without desugaring |
| Node     | 20.19  | For building the package only                     |

All iOS APIs newer than 14 must be behind `if #available(iOS …)`. All Android
APIs newer than 23 must be behind `if (Build.VERSION.SDK_INT >= …)`.

## Dual Capacitor version support

`peerDependencies` spans `>=7.0.0 <10.0.0`. Both majors are tested:

- TypeScript: `tsconfig.json` checks against `@capacitor/core` 7; `tsconfig.cap8.json`
  checks against `@capacitor/core@npm:@capacitor/core@^8.5.0`.
- The plugin API surface (`NativeNavigationPlugin`) is unchanged between v7 and
  v8 — no version-specific forks in the TypeScript code are needed.

## CSS variables injected by the plugin

When `contentInsetMode` is `"css"` (the default), the plugin writes these on
`document.documentElement`:

```
--cap-native-navigation-top      navbar inset (px)
--cap-native-navigation-right    right inset (px)
--cap-native-navigation-bottom   tabbar inset (px)
--cap-native-navigation-left     left inset (px)
--cap-native-navbar-height       navbar height (px)
--cap-native-tabbar-height       tabbar height (px)
```

## Custom elements (components.ts)

`defineNativeNavigationElements()` registers three custom elements:

| Element                           | Maps to                        |
| --------------------------------- | ------------------------------ |
| `<cap-native-navigation-provider>` | `NativeNavigation.configure()` |
| `<cap-native-navbar>`             | `NativeNavigation.setNavbar()` |
| `<cap-native-tabbar>`             | `NativeNavigation.setTabbar()` |

**Coalescing:** attribute changes are batched per microtask and serialized via a
`syncTail` promise chain. A rejected native call is swallowed (not an unhandled
rejection) so the queue stays alive.

---

## Events

Each event is emitted via both `NativeNavigation.addListener(...)` and a
`CustomEvent` on `window` under the name `capNativeNavigation:<eventName>`.

| Event name        | Payload type                          |
| ----------------- | ------------------------------------- |
| `navbarBack`      | `NativeNavigationBackEvent`           |
| `navbarItemTap`   | `NativeNavigationBarItemTapEvent`     |
| `tabSelect`       | `NativeNavigationTabSelectEvent`      |
| `safeAreaChanged` | `NativeNavigationSafeAreaChangedEvent`|
| `transitionStart` | `NativeNavigationTransitionEvent`     |
| `transitionEnd`   | `NativeNavigationTransitionEvent`     |

## What NOT to do

- Do not rename the bridge (`NativeNavigation`) without updating Swift, Java, and
  running `check-wiring`.
- Do not raise platform floors without updating `PLATFORM.md` and `check-wiring.mjs`.
- Do not remove or alter `/* This Source Code Form … */` headers in any source file.
- Do not add `sideEffects: false` to `package.json`.
- Do not merge `registry.ts` into `index.ts` or `components.ts` (creates a
  circular module graph).
- Do not declare `"type": "commonjs"` — the package is ESM-first.
- Do not add `CLAUDE.md` to the npm `files` array.
